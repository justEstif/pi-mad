FORGE REPORT

pi-mad — the personal skill shelf · idea-forge session
HARDENED

Subject

Reposition pi-mad from “curated BMAD-derived skills package” to a personal library — and decide whether the extension/allowlist machinery still earns its place.

Locked

  • pi-mad is a personal skill shelf: one resource type (skills; workflows are skills). No agents directory — agent-builder writes to pi’s own agents dir on demand.
  • Uniform all-dark: disable-model-invocation: true on every skill; opt in by naming it.
  • Discovery via a new pi_mad_search tool — suggests without loading or invoking.
  • Extension enforces the dark flags (pi update restores shipped SKILL.md).
  • Tags killed; search matches description text.
  • README shrunk to identity + install + pointer to skills/.
  • Knap allowed only inside generator skills (render/batch + validate gate); never in skill loading.
  • Native first: custom code only where pi has no answer.

Rejected, and why

  • Default-off allowlist & migration layer — double curation; commit-time curation suffices.
  • pi_mad_skills enable/disable manager — nothing left to manage under all-dark.
  • Per-project hot-set via settings filter — no native per-project flag override; restart tax.
  • Tags as a search index — maintenance surface; descriptions search better.
  • Distribution/product framing — audience is one; README now says so.
  • Agents as repo content — persistent personas reduce to skills + notes files.

Weak points that survived scrutiny

  • pi update restores shipped flags; the extension must re-enforce at startup.
  • disable-model-invocation is a pi extension field — silently ignored by other agentskills.io consumers.
  • All-dark gives up per-project memory; opt-in is per session, by name.
